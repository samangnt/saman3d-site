# Emergency Route — CrazyGames readiness review

Reviewed on 1 November 2026 for browser version 0.9. **The game is a candidate for Basic Launch, with testing and submission work remaining. It is not validated for Full Launch or approved by CrazyGames.**

This review compares the source and available browser/physics tests with the current official requirements. A code check or desktop simulation does not establish compatibility on a physical phone, Safari or a low-memory Chromebook.

| Area | Current evidence and status |
|---|---|
| Desktop size and file count | Pass in the prepared website bundle: approximately 44.5 MB and fewer than 50 files. The offline HTML is approximately 49.8 MB; ZIP compression is not the initial-download measurement. Without the SDK, the entire game must fit within 50 MB and 1,500 files. [Technical requirements](https://docs.crazygames.com/requirements/technical/) |
| Mobile homepage size | Not eligible with the current bundle: it exceeds the 20 MB initial-download threshold. This threshold concerns mobile-homepage eligibility, not a blanket ban on larger mobile games. [Technical requirements](https://docs.crazygames.com/requirements/technical/) |
| Runtime and asset paths | HTML5/WebGL, relative local runtime assets and embedded textures. No runtime Roblox or external asset-service dependency. Standalone and single-file HTTP startup checked. |
| Browser and hardware performance | Desktop Chromium checked. Physical Chrome/Edge, Safari, Android/iOS and 4 GB Chromebook performance remain unverified. Those are material gaps; emulator/desktop touch tests are insufficient. [Technical requirements](https://docs.crazygames.com/requirements/technical/) |
| Responsive UI | HUD bounds checked at all ten listed iframe sizes at the available DPR of 1.25; tablet spacing adjusted. DPR 1 readability, all menus/prompts, device notches, app safe areas and prolonged real-device use still need visual testing. [Gameplay requirements](https://docs.crazygames.com/requirements/gameplay/) |
| Physics | Pass for the tested driving scenario: fixed-step results match at 30, 60, 120, 144 and 165 Hz. Ground repairs, hospital approaches, twelve rings, landing and final organ carry have separate passing checks. |
| Inputs and audio | Keyboard/mouse and simulated phone joystick, pinch, jump, holds and flight controls checked. Ctrl is not a flight control. Native engine signal and audio-context recovery verified in the desktop browser; iOS interruption behavior still needs a real device. [Technical requirements](https://docs.crazygames.com/requirements/technical/) |
| Platform fullscreen | The standalone game retains its controls. Source code hides custom fullscreen controls and prevents automatic fullscreen on detected CrazyGames hosts/ancestors. This behavior has not been tested in the Developer Portal or CrazyGames App. Custom fullscreen controls are prohibited there. [Gameplay requirements](https://docs.crazygames.com/requirements/gameplay/) |
| Language and first-play flow | English UI and control hints are present. First visit currently requires PLAY, name entry and the lobby/start area. Full Launch's immediate/one-click gameplay entry is not implemented. [Gameplay requirements](https://docs.crazygames.com/requirements/gameplay/) |
| SDK | Not integrated. This is allowed for Basic Launch; Full Launch requires the SDK and gameplay start/stop integration. Gameplay events must reflect actual playable state. [Launch requirements](https://docs.crazygames.com/requirements/intro/), [Technical requirements](https://docs.crazygames.com/requirements/technical/) |
| Saved progress and profile | Coins, name and helicopter ownership currently use localStorage. Full Launch cloud progress is not configured: choose the Data module or Automatic Progress Save, and handle the applicable CrazyGames profile/guest flow. [Account and progress requirements](https://docs.crazygames.com/requirements/account-integration/) |
| Advertising and purchases | No external ads, paid currency or real-money purchases are implemented. The helicopter uses earned coins. Basic Launch has no monetization; any future ads must use the CrazyGames SDK and the required pause/mute/error handling. [Advertising requirements](https://docs.crazygames.com/requirements/ads/) |
| Cross-promotion and data | No player-facing outbound promotions, external login or player-data uploads found in the game controller. Names and progress stay in the browser. Public release scanning checks for credentials, personal paths and private files. |
| Age suitability and originality | The inspected game uses non-graphic emergency transport and closed organ containers. PEGI 12 suitability and editorial originality need publisher review. Recovered asset provenance is documented; this conversion does not itself establish redistribution rights. [Gameplay requirements](https://docs.crazygames.com/requirements/gameplay/) |
| Covers and preview videos | Not prepared as a CrazyGames submission set. Required covers: 1920×1080, 800×1200 and 800×800. The required landscape/portrait gameplay preview videos are also missing. [Cover and video specifications](https://docs.crazygames.com/requirements/game-covers/) |
| Quality guidelines | Controls, mission goals, progression and multiple repair stages exist. Several recent graphical/audio defects were repaired, but onboarding, pacing, consistent art, sound balance and a full human playthrough remain review work. These recommendations are distinct from mandatory requirements. [Quality guidelines](https://docs.crazygames.com/requirements/quality/) |
| Multiplayer | Not applicable: the game is single player. |
| Portal acceptance | No Developer Portal upload, QA-tool run, SDK preview or CrazyGames acceptance has occurred. GitHub Pages publication verifies the standalone website only. [Submission and QA process](https://docs.crazygames.com/requirements/intro/) |

The remaining Basic Launch work is real-browser/device testing, complete readable-UI and playthrough review, source-rights confirmation, cover/video preparation and the portal preview. Full Launch additionally needs SDK lifecycle events, the appropriate progress/profile integration and revised first-play onboarding. Mobile-homepage eligibility requires a substantially smaller initial bundle.
